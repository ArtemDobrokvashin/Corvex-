## Как устроены документы

- **Один документ — одна задача.** Никаких «глав 1–12» и дублирующих описаний: каждая
  тема описана в одном месте, остальные документы на неё ссылаются.
- **Русский — основной язык.** README, установка и эта карта продублированы на английском.
  Остальные документы на русском, чтобы не расходиться с фактическим состоянием кода.
- **Факт и план разделены.** [`STATUS.md`](STATUS.md) содержит только то, что проверено
  с указанием коммита. Всё непроверенное и запланированное — в [`ROADMAP.md`](ROADMAP.md).
  Если в документе написано «работает», рядом должно быть, при каких условиях это выяснили.
- **Граница доказательств указывается явно.** Успешная сборка Docker не равна пройденным
  тестам; прохождение unit-тестов не равно приёмке почтового клиента. Где проверка не
  выполнялась, это написано словами, а не скрыто.
- **Документ не старше кода.** Если изменение меняет поведение, контракт или команду
  запуска, соответствующий документ правится в том же PR.

## Служебные каталоги

| Путь | Что там |
|---|---|
| [`api/`](api/) | OpenAPI-спецификации: `auth-api.yaml`, `mail-api.yaml`, `chat-api.yaml`, `admin-api.yaml` |
| [`screenshots/`](screenshots/) | скриншоты интерфейса и правила их пересъёмки |
| [`design/`](design/) | референсы дизайна почтового интерфейса |
| [`ci/ci.yml`](ci/ci.yml) | готовый workflow проверки PR. Не подключён: у автоматизации нет права
  `workflows`. Включается одной командой — см. шапку файла |

Отдельно, вне `docs/`:

| Путь | Что там |
|---|---|
| [`../scripts/README.md`](../scripts/README.md) | все служебные скрипты: установка, бэкап, приёмка, диагностика |
| [`../experiments/`](../experiments/) | лабораторные образцы James и AV-шлюза, используемые проверками |
| `services/*/README.md` | особенности конкретного сервиса (IMAP, POP3, James-адаптер) |
