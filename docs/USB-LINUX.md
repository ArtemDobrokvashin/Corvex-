# Corvex на USB: загружаемая Linux-система для теста

Да, можно — и это хороший способ проверить стек, не трогая рабочий компьютер.
Но не «live-флешкой»: Docker и сборка 12 сервисов требуют записываемой системы и
много места. Ниже — три варианта, честные цифры по объёму и то, где вариант ломается.

Короткий ответ про объём:

| Носитель | Хватит на | Реальность |
|---|---|---|
| 32 ГБ | почти ничего | не хватит: только Ubuntu и образы без кэша сборки |
| **64 ГБ** | минимальный тест: запуск, вход, почта себе | впритык; после сборки почти не остаётся места |
| **128 ГБ** | полноценный тест: сборка, данные, копия, место под рост | **рекомендуемый размер** |
| 256 ГБ | тест с нагрузкой и историей копий | если носитель быстрый, иначе смысла мало |

Важнее объёма — **скорость**. Обычная флешка пишет 10–30 МБ/с, и первая сборка
12 Java-сервисов на ней занимает 1,5–3 часа вместо 10–30 минут; плюс флешка не любит
постоянную запись Docker. Поэтому:

- **лучший вариант:** NVMe SSD (или SATA SSD) в USB 3.2-корпусе — 128 или 256 ГБ,
  работает как обычный диск, сборка идёт с нормальной скоростью;
- **приемлемый:** быстрая флешка USB 3.2 (не USB 2.0!), 128 ГБ, с оговорками по скорости;
- **не подходит:** microSD через дешёвый кардридер и любая флешка USB 2.0.

## Куда уходит место

Считано по этому репозиторию, а не «на глазок»:

| Что | Объём | Можно ли уменьшить |
|---|---|---|
| Ubuntu Server 24.04 LTS (система) | 6–8 ГБ | да, minimal install |
| Docker Engine и containerd | ~0,7 ГБ | нет |
| Базовые образы (postgres, james, elastic, rabbitmq, nginx, clamav, spamd) | 6–9 ГБ | нет, они нужны |
| Собранные 12 Java-сервисов и фронтенд | 6–10 ГБ | нет |
| Кэш сборки BuildKit и Maven | 15–25 ГБ | да: `docker builder prune` после сборки экономит 15+ ГБ |
| Данные теста: несколько ящиков, вложения | 2–5 ГБ | да |
| Индекс Elasticsearch | 1–3 ГБ | нет |
| Копия (только для теста!) | 3–10 ГБ | да, одну и без истории |
| Запас, чтобы система не встала на 100 % | 10–15 % | нет |

Итого без кэша сборки: **35–50 ГБ**. Поэтому 64 ГБ — впритык, 128 ГБ — спокойно.
Для сравнения: [`capacity.py`](../scripts/capacity.py) для 50 ящиков за год считает 200 ГБ
на сервере и отдельный носитель под копии — но это боевой расчёт, а не тест.

## Вариант A. Полная Ubuntu на носителе (рекомендуется)

Система ставится на носитель как на обычный диск: загрузчик, разделы, всё своё.
Работает после выключения, ничего не теряется, Docker ставится штатно.

**Что нужно:** носитель 128 ГБ, **второй** носитель 2 ГБ с установочным ISO
(или Ventoy на нём), компьютер, с которого можно загрузиться с USB.

1. **Записать установщик** на маленькую флешку: Ubuntu Server 24.04 LTS
   (`ubuntu-24.04.x-live-server-amd64.iso`), через Rufus/balenaEtcher/`dd`.
   Server, а не Desktop: лишние 2 ГБ и графическая оболочка на сервере не нужны.
2. **Загрузиться с установщика**, выбрать установку **на целевой носитель**, а не на
   внутренний диск. Проверить это дважды: установщик по умолчанию видит первый диск.
3. **Разметка на 128 ГБ:** один раздел `ext4` на всё, без отдельного `/home` и **без
   swap-раздела** — swap на флешке убивает носитель и бесполезен. Если нужен запас
   по памяти, используйте `zram` (сжатие в RAM), а не раздел.
4. **`noatime`** в `/etc/fstab` — меньше записи на носитель:
   `UUID=... / ext4 defaults,noatime 0 1`.
5. **Загрузиться с носителя**, поставить стек обычным путём:
   [`UBUNTU.md`](UBUNTU.md), начиная с шага 1.

Что важно помнить про этот вариант:

- GRUB ставится на носитель; если при установке выбрать «загрузчик на внутренний
  диск», компьютер начнёт зависеть от флешки — этого не делаем;
- скорость записи определяет всё: на USB 3.2 SSD сборка идёт как на обычном сервере,
  на флешке — часами, и это нормальный результат, а не дефект;
- носитель изнашивается: для регулярного теста лучше SSD в корпусе, а не флешка.

## Вариант B. Live-USB с сохранением (persistent)

Ubuntu с флешки, изменения хранятся в файле `casper-rw`. Плюс: ничего не ставится на
компьютер. Минус: размер сохранения ограничен 4 ГБ на FAT32 — а Docker только образами
занимает больше. С `casper-rw` как отдельным ext4-разделом ограничение снимается, но
live-режим всё равно медленнее и хуже переживает обновления.

Годится, чтобы **посмотреть интерфейс** уже собранного стека или запустить `preflight.py`.
Для сборки и полноценного теста — вариант A.

## Вариант C. Не носитель, а виртуалка

Если цель — «поставить всё для теста», а не именно флешка: Ubuntu Server в VirtualBox,
VMware или Hyper-V на 4 vCPU / 16 ГБ RAM / 120 ГБ диска даёт то же самое, быстрее и
без износа. Носитель нужен, когда тест должен идти **на конкретном железе** или когда
на компьютере нельзя ставить виртуалку.

## Что сделать сразу после установки, чтобы не поймать ложные отказы

1. `sudo ./scripts/prepare-ubuntu.sh --check` — покажет, чего не хватает
   (`docs/UBUNTU.md` §1). На свежей системе он обязательно найдёт:
   `vm.max_map_count=65530` — без 262144 Elasticsearch уйдёт в рестарт-петлю.
2. `sudo ./scripts/prepare-ubuntu.sh --user $USER` — поставит Docker, группу и sysctl.
3. Перелогиниться (`newgrp docker`), иначе `docker` попросит sudo.
4. `./scripts/first-run.sh --domain mail.example.ru` (или без домена — будет
   самоподписанный сертификат).
5. `python3 scripts/ubuntu_origin.py --env .env --ip <IP>` — иначе при входе по IP
   браузер получит отказ `Origin`, и в логах не будет ни строки.
6. `python3 scripts/preflight.py`, затем `docker compose up -d --build`.
7. Сразу копия: `sudo mkdir -p /srv/backup && sudo chown $USER /srv/backup`
   и `./scripts/backup.sh --backup-root /srv/backup`.

После сборки, если место кончается: `docker builder prune -f` освобождает кэш сборки
(15–25 ГБ), образы при этом остаются. `docker system prune` **не** использовать:
он удаляет и то, что нужно работающему стеку.

## Чего этот тест не докажет

- **Производительность.** Флешка или SSD по USB — не серверный диск; цифры
  производительности с них переносить на боевое железо нельзя.
- **Почту наружу.** Нужны домен, MX, PTR и открытый 25 — ни флешка, ни локальная сеть
  этого не дают.
- **72 часа наблюдения.** Их считают на боевом сервере, а не на тестовом носителе;
  здесь снимается только baseline.
- **Надёжность хранения.** USB-носитель отключают, роняют и теряют. Копии держите на
  другом носителе — правило то же, что для сервера.

## Частые ошибки

| Симптом | Причина |
|---|---|
| Установщик не видит носитель | включён Secure Boot/RAID-режим SATA, или носитель в USB 2.0-порту |
| После установки грузится старый Windows | загрузчик поставлен на внутренний диск, а не на носитель |
| Система встала через день | флешка исчерпала ресурс записи: Docker и журналы пишут постоянно, нужен SSD |
| Сборка идёт часами | скорость записи носителя; проверить `dd if=/dev/zero of=./test bs=1M count=1024 oflag=direct` |
| Elasticsearch перезапускается | не выставлен `vm.max_map_count=262144` |
| Интерфейс открывается по имени, но не по IP | в `.env` нет адреса в `CORVEX_WEB_ORIGINS` |
