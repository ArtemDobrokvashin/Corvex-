# 8. Инструкция по развёртыванию на Windows Server

> К пункту 8 формата вывода. Рассчитана на администратора Windows без опыта Docker;
> каждый шаг — с проверкой результата. Время полного первого подъёма: 1,5–3 часа,
> из них большая часть — DNS и сертификаты, не сама система.

## Шаг 1. Подготовка сервера и сети

- Windows Server 2019/2022, 16 CPU / 32 ГБ RAM / 1 ТБ SSD (рекомендация ТЗ §8.1;
  минимум 8/16/500 работает для пилота до ~200 ящиков);
- статический публичный IP, у провайдера **открыт исходящий и входящий 25 порт**
  (многие провайдеры закрывают — уточнить до старта!);
- в брандмауэре Windows и на периметре открыть входящие: **443, 25, 587, 993, 143,
  995, 110** (80 — для редиректа и Let's Encrypt);
- имя сервера: `mail.company.local` (дальше в примерах ваш домен).

## Шаг 2. Docker: важное предупреждение и два варианта

Docker Desktop **официально не поддерживается на Windows Server** (нет поддержки
Microsoft/Docker, для компаний >250 сотрудников нужна платная подписка), а нативный
Docker Engine на Windows запускает только Windows-контейнеры. Поэтому:

- **Вариант A (продакшен, рекомендуется):** на Windows Server включается Hyper-V
  и создаётся Linux-VM (Ubuntu Server 24.04 LTS, все vCPU/RAM минус 2/4 ГБ хосту,
  диск — динамический VHDX на SSD). Docker Engine ставится в VM одной командой
  `curl -fsSL get.docker.com | sh`; проброс портов — внешним виртуальным
  коммутатором Hyper-V (VM получает свой IP в сети, NAT не нужен).
  Для администратора внешне ничего не меняется: сервер один, Windows осталась.
- **Вариант B (пилот по букве ТЗ):** Docker Desktop на отдельной машине Windows
  10/11 или, на свой риск, на Server. Для пилота на 20–50 ящиков приемлемо.

Дальнейшие шаги одинаковы (в варианте A команды выполняются в VM по SSH,
в варианте B — в PowerShell).

## Шаг 3. Получение проекта

```powershell
git clone <адрес репозитория> C:\Corvex
cd C:\Corvex
```

## Шаги 4–5. Секреты, ключи и `.env` (один скрипт)

```powershell
.\scripts\first-run.ps1   # НЕ копируйте .env.example вручную до этого шага
notepad .env              # домены, LDAP при наличии AD, получатели алертов (вНЕШНИЙ ящик!)
```

Скрипт: генерирует RSA-ключ подписи JWT в `infra/secrets`, самоподписанный TLS на
90 дней для пилота в `infra/certs` и создаёт `.env`, заменяя каждый плейсхолдер
**отдельным** случайным секретом. Подробности и Linux-эквивалент: [INSTALL.md](INSTALL.md) шаги 4–5.
**Проверка:** существуют `infra\secrets\jwt_private.pem`, `infra\certs\fullchain.pem`, `.env` без значений `change-me...`.

## Шаг 6. Настоящий TLS-сертификат (для продакшена)

- Публичный домен: Let's Encrypt — `win-acme` на хосте или certbot-контейнер;
  положите `fullchain.pem`/`privkey.pem` в `infra/certs` (общие для nginx, IMAP,
  POP3 — один сертификат на имя `mail.<домен>`).
- Внутренний домен компании: сертификат корпоративного CA, корневой CA должен быть
  в доверенных на всех клиентских машинах (групповой политикой).

## Шаг 7. DNS — без этого почта не заработает (чек-лист)

| Запись | Значение | Зачем |
|---|---|---|
| `A mail.company.local` | публичный IP сервера | веб, IMAP, SMTP клиенты |
| `MX company.local` | `10 mail.company.local` | куда Интернет шлёт вам почту |
| `PTR` (у провайдера) | `mail.company.local` | без rDNS крупные провайдеры режут почту |
| `TXT @` (SPF) | `v=spf1 mx -all` (на пилоте `~all`) | кто вправе слать от вашего домена |
| `TXT corvex1._domainkey` (DKIM) | публичный ключ из админки (Настройки → Почта → DKIM) | подпись исходящих |
| `TXT _dmarc` | `v=DMARC1; p=none; rua=mailto:dmarc@company.local` → через месяц `p=quarantine` | политика подделок и отчёты |
| `CNAME autoconfig`, SRV `_imaps._tcp` и т.п. | на `mail.company.local` | автоконфиг Thunderbird/Outlook — пользователи не вводят серверы руками |

## Шаг 8. Запуск

```powershell
docker compose up -d --build            # первая сборка 12 сервисов: 10–25 минут
docker compose --profile monitoring up -d
docker compose ps                       # все сервисы должны стать healthy
```

**Проверка:** `https://mail.company.local` открывает экран входа;
`docker compose ps` не показывает `unhealthy`/`restarting`.

## Шаг 9. Первоначальная настройка (проектное состояние после этапов 1 и 5)

> ⚠️ На текущую дату эндпоинтов входа ещё нет — веб-интерфейс работает в демо-режиме
> (см. [READINESS.md](READINESS.md)). Шаги ниже описывают целевое поведение после
> этапов 1 и 5 плана разработки; актуальные дымовые тесты сегодняшнего состояния —
> в [INSTALL.md](INSTALL.md) шаг 9.

1. Первый вход — суперадминистратор, создаваемый сидом этапа 1 (пароль задаётся
   переменной окружения при первом старте, смена при первом входе обязательна, 2FA предлагается сразу).
2. Админ-панель → Настройки: домены почты, лимит размера письма (25 МБ), квота по
   умолчанию (5 ГБ), порог спама (5.0).
3. Если есть AD: Настройки → Интеграция LDAP (LDAPS URL, база поиска, сервисная
   учётка только на чтение) → «Проверить соединение» → включить синхронизацию;
   группы AD сопоставляются группам Corvex вручную в том же экране.
4. Создайте тестового пользователя, проверьте цепочки шага 10.

## Шаг 10. Приёмочные дымовые тесты (15 минут)

```powershell
# SMTP приём извне (с другой машины/сети): отправьте письмо с внешней почты на тестовый ящик
# IMAP (PowerShell + OpenSSL из Git for Windows или WSL):
openssl s_client -connect mail.company.local:993 -crlf   # LOGIN, LIST, SELECT INBOX
# Веб: вход, отправка письма наружу, получение ответа, поиск по письму
# Чат: две вкладки браузера — сообщение появляется без обновления
# Алертинг: docker compose stop chat-service → письмо алерта за ≤3 мин → start
```

Внешняя проверка доставляемости: сервис mail-tester.com должен дать ≥9/10
(SPF/DKIM/DMARC/rDNS все зелёные).

## Шаг 11. Резервное копирование

- Задание Планировщика Windows ежедневно в 02:30: `powershell -File C:\Corvex\scripts\backup.ps1 -BackupRoot D:\CorvexBackup`;
- папку копий выносить на **другой физический носитель/сетевое хранилище**
  (бэкап на том же SSD не защищает ни от смерти диска, ни от шифровальщика);
- раз в квартал — учебное восстановление на стенде (процедура в docs/10 §10.5).

## Шаг 12. Обновление и откат

```powershell
git pull                                # или свежий архив релиза
docker compose up -d --build            # Flyway применит новые миграции сам
```

Откат: вернуть теги образов/коммит и повторить `up -d`; миграции только
аддитивные, поэтому старый код со новой схемой совместим в пределах релиза.

## Типовые проблемы

| Симптом | Причина | Лечение |
|---|---|---|
| Внешняя почта не приходит | MX/PTR не успели обновиться или закрыт 25 | `nslookup -type=mx`, проверка порта извне, TTL DNS |
| Ваша почта уходит в спам у получателей | нет DKIM/PTR, `SPF -all` до настройки всех отправителей | mail-tester, шаг 7 |
| Outlook: «сертификат не доверенный» | имя в сертификате ≠ `mail.<домен>` или самоподписанный пилот | шаг 6 |
| Контейнеры unhealthy по кругу | не хватает RAM (ES+ClamAV тяжёлые) | минимум 16 ГБ; на пилоте отключить профиль monitoring |
| Письма без вложений у получателя | `AV_STATUS=ERROR` при недоступном ClamAV (fail-closed) | проверить clamav, вложения разблокируются повторным сканом |
