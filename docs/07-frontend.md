# 7. Frontend: структура, маршрутизация, состояние

> К пункту 7 формата вывода. Код — [`frontend/`](../frontend), реально собирается
> (`npm run build` даёт два бандла: современный и legacy для Chrome 109).

## 7.1. Стек и совместимость с Windows 7 / Chrome 109

| Вопрос | Решение |
|---|---|
| Фреймворк | React 18 + TypeScript, сборка Vite 5 |
| Chrome 109 | `@vitejs/plugin-legacy` → Babel (`browserslist: chrome >= 109` в `package.json`) + core-js полифилы; современным браузерам отдаётся лёгкий modern-бандл, старым — legacy |
| Стили | Tailwind CSS **3** + Autoprefixer; системные шрифты (Segoe UI) — веб-шрифты из CDN не нужны, что важно для изолированных сетей |
| Роутинг | react-router-dom 6, модули через `lazy()` (админка не грузится у обычных пользователей) |
| Состояние | Zustand (сессия/права/UI); серверные данные в стор не копируются — каждый экран ходит в API |
| Реальное время | `@stomp/stompjs` + SockJS-fallback (`api/chatSocket.ts`) |
| XSS | HTML писем — только после санитизации на сервере + DOMPurify на рендере Markdown в чате |
| Яндекс браузер / Edge / Firefox | Chromium-based/современные — получают modern-бандл, отдельно проверяются E2E-матрицей (docs/10) |

## 7.2. Структура `src/`

```
src/
├── main.tsx                  # роутер: /login и оболочка с /mail /chat /admin (lazy)
├── index.css                 # Tailwind + touch-цели для мобильных
├── app/AppShell.tsx          # единая оболочка: боковое меню, бейджи уведомлений, статус, плашка демо
├── store/sessionStore.ts     # Zustand: пользователь, permissions, helper has()
├── api/
│   ├── httpClient.ts         # Bearer в памяти, refresh-cookie, авто-refresh на 401
│   ├── chatSocket.ts         # STOMP-клиент чата
│   └── demoData.ts           # УЧЕБНЫЕ данные витрины без бэкенда (см. ниже)
└── features/
    ├── auth/LoginPage.tsx    # вход + второй шаг TOTP
    ├── mail/MailPage.tsx     # папки → список → письмо, редактор, квота, AV-статус вложений
    ├── chat/ChatPage.tsx     # комнаты, сообщения (Markdown), реакции, треды, read-only каналы
    └── admin/AdminPage.tsx   # группы и чекбоксы 24 прав, здоровье сервисов
```

При росте внутри feature-папок добавляются `components/`, `hooks/`, `api.ts` этой
фичи; переиспользуемые контролы выносятся в `components/ui`.

## 7.3. Адаптивность (ТЗ §10.2)

- ≥1280px: почта в три столбца (папки/список/письмо), чат — список комнат + лента;
- планшет: два столбца, письмо — поверх списка с кнопкой «назад»;
- смартфон от 320px: один столбец, навигация модулей — горизонтальная панель
  сверху, touch-цели ≥40px (`@media (pointer: coarse)`).

## 7.4. Производительность (ТЗ §10.4)

- code splitting по роутам + vendor-чанк; статика с хэшами кэшируется nginx на год
  (`frontend/nginx-spa.conf`);
- списки писем/сообщений — курсорная пагинация от API; виртуализация списков
  (окно рендера) — этап 3 плана, API к ней уже готов курсором;
- оптимистичная отправка в чате: сообщение рисуется сразу с `clientMessageId`
  и подтверждается серверной копией из STOMP-топика (дедуп по тому же id).

## 7.5. Про демо-режим честно

Если gateway не отвечает (например, витрина без поднятого бэкенда), LoginPage
переводит UI в **помеченный жёлтой плашкой демо-режим** на данных `api/demoData.ts`:
экраны почты, чата и админки полностью кликабельны (чтение писем, отправка,
реакции, переключение прав). Это инструмент приёмки интерфейса до готовности
бэкенда; в продакшене `docker compose up` убирает демо автоматически — запросы
идут тем же `apiFetch` по реальным контрактам `docs/api/*.yaml`.
