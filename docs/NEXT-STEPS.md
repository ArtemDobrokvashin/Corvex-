# Что осталось сделать со мной

План на ближайшие дни: здесь только то, что **нельзя** сделать без вас — ноутбука, браузера,
консоли Google или доступа к серверу. Всё, что можно сделать без вас, уже сделано и лежит
в `main`; доказательства — в [`STATUS.md`](STATUS.md).

Правило прежнее: пункт считается закрытым, когда есть вывод команды или скриншот **и**
строка-доказательство в `STATUS.md`. «Работает» без этого — мнение.

## Как читать таблицу

| Кто | Что делает | Почему не автоматизируется |
|---|---|---|
| **Вы** | действия в браузере и на ноутбуке | нужен ваш аккаунт, ваша машина или ваш провайдер |
| **Я** | разбор вывода, правки, тесты, документация, коммит | после каждого шага вы присылаете результат |

означает, что OAuth придётся проверять на незнакомой конфигурации.

## День 1. P1 — живой вход через Google (около 40 минут, из них 30 — консоль)

Что нужно от вас: браузер с вашим Google-аккаунтом. Секреты в чат не присылать.

1. **Проект.** <https://console.cloud.google.com> → новый проект `corvex-pilot`.
   Если проект не создаётся — проверьте двухэтапную аутентификацию у владельца: с 13 мая
   2025 Google не даёт создать проект без неё.
2. **OAuth consent screen** → тип **External** → заполнить название и почту поддержки →
   в **Test users** добавить свой адрес.
3. **Credentials → Create credentials → OAuth client ID → Web application.**
   Не «Desktop»: Desktop принимает только `http://localhost:<порт>` без пути.
4. **Authorized redirect URI** — ровно эта строка, посимвольно:

   ```text
   http://localhost:8080/api/v1/mail/external-accounts/oauth/callback
   ```

   `localhost` и `127.0.0.1` для Google — разные хосты. Слэш на конце — тоже разница.
5. Скопируйте **Client ID** и **Client secret**. Вставьте их в `.env` на ноутбуке
   (не в чат):

   ```text
   CORVEX_PUBLIC_BASE_URL=http://localhost:8080
   CORVEX_WEB_ORIGINS=http://localhost:8080
   CORVEX_OAUTH_GOOGLE_CLIENT_ID=<client id>
   CORVEX_OAUTH_GOOGLE_CLIENT_SECRET=<client secret>
   ```

6. Поднимите стенд и пройдите сценарий:

   ```bash
   docker compose --profile local-oauth up -d
   ```

   Вход `http://localhost:8080` (именно `localhost`, не `127.0.0.1`) → «Почта» →
   подключить внешний ящик → Google → согласие → возврат на `/mail?oauth=connected…` →
   в списке появился ящик → сбор писем.

7. **Отзыв согласия.** Google → «Сторонние приложения» → удалить доступ. Следующая
   попытка сбора должна дать `reauthRequired` и `409`, а не бесконечный 401. Повторный
   вход восстанавливает сбор.

Что прислать мне: сколько писем собралось, код ответа после отзыва согласия, текст ошибки
целиком, если она есть. Больше ничего.

Что я сделаю после: строку-доказательство в `STATUS.md`, при расхождении — правку кода или
документации.

> **Срок годности результата — 7 дней.** В статусе Testing Google выдаёт refresh token на
> неделю. После этого сбор останавливается с `reauthRequired` — это политика провайдера,
> а не дефект. Для постоянной работы нужен статус Production и верификация приложения
> (restricted scope `https://mail.google.com/`). Это отдельное решение, не «ещё один шаг
> установки».

## День 2. P4 — установка с нуля в пустом каталоге (около 2 часов, из них 30 минут — сборка)

Что нужно: ноутбук с Docker и 60–80 ГБ свободного места. Данные текущего стенда не трогаем.

```bash
git clone https://github.com/ArtemDobrokvashin/Corvex-.git corvex-clean
cd corvex-clean
./scripts/first-run.sh
python3 scripts/preflight.py
docker compose -p corvex-fresh up -d --build
docker compose -p corvex-fresh ps
```

> **Почему `-p corvex-fresh`.** В `docker-compose.yml` зафиксировано `name: corvex`,
> поэтому клон в новом каталоге — это **не** чистая установка: compose подхватит тома
> старого стенда. Пароль PostgreSQL задаётся один раз при инициализации тома, и при
> другом пароле в новом `.env` сервисы падают с
> `FATAL: password authentication failed for user "corvex"`. Отдельное имя проекта
> создаёт новые тома, а данные старого стенда остаются нетронутыми.
> `preflight.py` предупреждает об этом строкой `project volumes`.

Проверки после первого запуска — [`INSTALL.md`](INSTALL.md) §9: вход, `401` на
`/api/v1/auth/me`, JWKS, миграции `V1…V14`, отсутствие заглушек, `SMTP listener disabled`,
календарь с напоминанием, `scripts/alert_e2e.py`.

Если что-то падает — присылайте **первую** ошибку целиком, не хвост лога.

Что я сделаю после: разбор, правку, тест на найденный класс ошибки.

## День 3. P3 — восстановление из копии (около полутора часов)

Что нужно: Windows-хост и свободный диск под копии. Порядок важен: сначала копия, потом
восстановление в **изолированный** проект, потом сверка.

```powershell
powershell -ExecutionPolicy Bypass -File scripts\backup.ps1 -BackupRoot D:\CorvexBackup

powershell -ExecutionPolicy Bypass -File scripts\restore.ps1 `
  -BackupDir D:\CorvexBackup\<timestamp> -ProjectName corvex-restore-drill -DataOnly -Force

powershell -ExecutionPolicy Bypass -File scripts\restore_verify.ps1 `
  -BackupDir D:\CorvexBackup\<timestamp> -ProjectName corvex-restore-drill
```

Контрольный ящик после восстановления: письмо, вложение, событие календаря и комната чата
открываются. Ожидаемый итог `restore_verify.ps1` — четыре маркера `<db>_logical_match`
и четыре совпавших тома.

Что я сделаю после: если `backup.ps1` упадёт на Windows — это первый настоящий прогон,
и правки будут по факту, а не по чтению.

## День 4. Разбор DLQ и наблюдение (около часа)

Что нужно: доступ к стенду. **Ничего не purge'ить и не перезапускать «на удачу».**

```bash
./scripts/verify-dlq-resilience.sh --baseline
```

Скрипт печатает счётчики очередей. В DLQ `mail.spam.inbound.dlq` — 45 сообщений, shovel не
включён, автоматического возврата нет: разбирать вручную, по одному, глядя на заголовок
ошибки. Порядок и что считать нормой — [`OPERATIONS.md`](OPERATIONS.md).

Затем 72 часа наблюдения — **на боевом железе после переезда**, не на ноутбуке: алерты
приходят на внешний ящик, память контейнеров не растёт, очереди не копятся. Пока переезда
нет, на ноутбуке снимается только baseline — точка сравнения, а не пройденный этап
(см. [`OPERATIONS.md`](OPERATIONS.md) §2).

## Что от вас не требуется

- Присылать пароли, секреты и токены в чат. Только Client ID и тексты ошибок.
- Запоминать команды: каждый шаг выше — одна команда, и я разбираю её вывод.
- Делать несколько шагов сразу. По одному — иначе непонятно, что именно сломалось.
- Ставить «фишки»: новые функции чата, календаря и диска заморожены до пилота.
