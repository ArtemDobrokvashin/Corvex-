# Требования к серверу

Что нужно, чтобы Corvex работал на своём сервере: железо, диск, сеть, домен, сертификат и
доступы. Расчёт — на **50 почтовых ящиков**. Для другого числа ящиков есть формула и
таблица ниже.

Corvex — свободное ПО под Apache-2.0. Платных лицензий, подписок и платы за пользователя
нет: весь стек работает на бесплатных компонентах (Docker, PostgreSQL, RabbitMQ, Redis,
Elasticsearch, SpamAssassin, ClamAV) и сертификате Let's Encrypt.

## 1. Сервер

| Параметр | Требование |
|---|---|
| Форм-фактор | 1 физический сервер или 1 виртуальная машина; всё развёртывание — один `docker compose` |
| CPU | 4–6 vCPU |
| RAM | **16 ГБ минимум, 24 ГБ с мониторингом** |
| Системный диск | 100 ГБ SSD — ОС, образы контейнеров (~25 ГБ), кэш сборки |
| Диск данных | 100 ГБ SSD — почта, базы, поисковый индекс, файлы |
| Тип диска | только SSD |
| Резервные копии | отдельный носитель 100–200 ГБ: внешний диск, NAS или сетевая папка |
| ОС | Windows Server 2019/2022 **или** Ubuntu Server 24.04 LTS |
| Лицензии | Windows Server — существующая корпоративная; остальное бесплатно |

Распределение памяти при 16 ГБ: Elasticsearch ~2,5 ГБ, PostgreSQL ~2 ГБ, ClamAV 2–3 ГБ,
остальное — 12 Java-сервисов, RabbitMQ, Redis, шлюз и frontend. На 8 ГБ контейнеры падают
по памяти.

На Windows нужна Linux-VM в Hyper-V: сервисные образы собраны под Linux. Порядок —
в [`INSTALL.md`](INSTALL.md).

### Расчёт диска

Диск данных ≈ `ящики × квота × 0,20 × 0,75` (заполнение 20 %, дедупликация вложений
25 %) плюс ~15 ГБ на метаданные, индекс и мониторинг.

```bash
python scripts/capacity.py --mailboxes 50
python scripts/capacity.py --mailboxes 100 --quota-gib 10 --years 2
python scripts/capacity.py --mailboxes 50 --json
```

| Ящиков | Почта за первый год | Диск данных | Резервные копии | RAM | CPU |
|---:|---:|---:|---:|---:|---:|
| 50 | ~38 ГиБ | 100 ГБ | 100–200 ГБ | 16–24 ГБ | 4–6 |
| 100 | ~75 ГиБ | 200 ГБ | 200 ГБ | 16–24 ГБ | 6 |
| 1000 | ~750 ГиБ | 1,3 ТБ | 1,7 ТБ | 32 ГБ | 8–16 |

Квота 5 ГиБ на ящик — потолок, а не занятое место. Квоты меняются в админке
(**Администрирование → Квоты**) без перезапуска.

## 2. Сеть

| Требование | Назначение |
|---|---|
| Статический публичный IPv4, не за NAT/CGNAT провайдера | MX-записи и приём почты |
| Возможность установить PTR-запись (обратная зона) = `mail.<домен>` | доставляемость у Gmail, Mail.ru, Яндекса |
| Входящий TCP 25 | приём почты от внешних серверов |
| Исходящий TCP 25 | отправка почты наружу |
| Входящие TCP 80, 443 | веб-интерфейс, API, чат, выпуск сертификата |
| Входящий TCP 587 | отправка из почтовых клиентов (Thunderbird, Outlook) |
| Входящие TCP 143, 993 (IMAP), 110, 995 (POP3) | доступ из почтовых клиентов; выключены до приёмки |
| Исходящий доступ в интернет (443) | обновление антивирусных сигнатур, пакеты, Let's Encrypt |

Порты 5432 (PostgreSQL), 6379 (Redis), 5672 (RabbitMQ), 9200 (Elasticsearch) наружу не
публикуются: они работают во внутренней сети Docker.

Если провайдер закрывает исходящий 25 и открыть его нельзя, нужен внешний SMTP-релей —
это отдельный внешний сервис и отдельные расходы.

## 3. Домен и DNS

Нужен домен для почты (например `company.ru`) и доступ к его DNS-зоне — собственный или
через заявку провайдеру. Записи вносятся по шагу «DNS» в [`INSTALL.md`](INSTALL.md).

| Запись | Значение | Назначение |
|---|---|---|
| `A` | `mail.company.ru` → публичный IP сервера | веб-интерфейс и почта |
| `MX` | `company.ru` → `mail.company.ru`, приоритет 10 | приём почты на домен |
| `TXT` (SPF) | `v=spf1 mx -all` | защита от подделки отправителя |
| `TXT` (DKIM) | `corvex1._domainkey` — публичный ключ | подпись писем |
| `TXT` (DMARC) | `_dmarc` → `v=DMARC1; p=quarantine; ...` | политика для получателей |
| `TXT` (autoconfig) | `autoconfig.company.ru` | автопастройка Outlook/Thunderbird |
| `PTR` | у провайдера: IP → `mail.company.ru` | проверка обратной зоны |

Для внутреннего стенда без внешней почты домен и PTR не требуются: достаточно локального
имени и самоподписанного сертификата. Внешняя переписка в этом режиме не проверяется.

## 4. Сертификат

| Вариант | Что нужно |
|---|---|
| Публичный домен | открытый порт 80; Let's Encrypt выпускается автоматически и бесплатно |
| Внутренний домен | сертификат корпоративного УЦ на `mail.company.ru` (`.pem`: сертификат + ключ) |
| Стенд | самоподписанный на 90 дней создаётся `scripts/first-run.ps1`; браузер предупреждает |

Для IMAP и POP3 нужны `imap.p12` и `pop3.p12` с SAN на почтовое имя; создание —
в [`TESTING.md`](TESTING.md), раздел «IMAP и POP3».

## 5. Доступы и учётные записи

| Что | Назначение |
|---|---|
| Локальный администратор сервера или SSH в Linux-VM | установка и запуск |
| Право менять DNS-зону либо контакт, вносящий записи по заявке | SPF/DKIM/DMARC/MX |
| Отдельный внешний почтовый ящик для алертов (не на этом сервере) + пароль приложения | алерт при падении самого сервера |
| 2–3 тестовых ящика на домене организации | приёмка: два пользователя, групповые действия, файлы |
| Один ящик на внешнем провайдере (Mail.ru / Яндекс / Gmail) | проверка почты «снаружи» |
| Учётные данные корпоративного прокси, если выход в интернет через него | обновление антивируса и выпуск сертификата |

AD/LDAP не требуется: учётные записи создаются в веб-интерфейсе, первый суперадминистратор —
через мастер первого запуска.

## 6. Требования к хосту

1. **Исключения корпоративного антивируса/EDR** для Hyper-V, Docker и томов данных.
   Без них сканер блокирует файлы виртуальных дисков и сервисы падают. Альтернатива —
   отдельный хост под пилот.
2. **Целевое хранилище резервных копий**: отдельный диск, NAS или сетевая папка. Минимум
   2 копии, рекомендуемая глубина истории — месяц. Копия на том же диске не считается.
3. **Часы хоста синхронизированы по NTP**: расхождение времени ломает TLS, JWT и подписи.
4. **Плановое окно обслуживания** не менее 2 часов в неделю для обновлений и проверки
   восстановления.
5. **Ресурсы под Hyper-V** при установке на Windows: Linux-VM получает 4–6 vCPU и 16–24 ГБ
   RAM, остальное остаётся хосту.

## 7. Ограничения

| Ограничение | Последствие | Что делать |
|---|---|---|
| Провайдер не открывает порт 25 | почта не ходит совсем | проверить до работ; при отказе — внешний SMTP-релей |
| Нет PTR или он не совпадает с именем | письма в спаме у получателей | запрашивать PTR вместе с IP |
| Новый IP без репутации | первые дни часть писем в спаме | отправлять постепенно, следить за DMARC-отчётами |
| 8–12 ГБ RAM | контейнеры падают по памяти | 16 ГБ минимум, 24 ГБ с мониторингом |
| Корпоративный антивирус на хосте | блокирует тома Hyper-V/Docker | исключения или отдельный хост |
| Бэкапы на том же диске | потеря данных при отказе диска или шифровальщике | отдельный носитель + проверенное восстановление |

Состояние готовности, при котором сервер имеет смысл выделять, — в [`STATUS.md`](STATUS.md).
Порядок установки — в [`INSTALL.md`](INSTALL.md).
