# Что нужно для запуска Corvex на сервере

Документ для согласования с руководителем и ИТ. Слева — что нужно, справа — зачем и что
будет, если этого не будет. Все цифры обоснованы в [`SIZING.md`](SIZING.md) и считаются
скриптом `scripts/capacity.py`; их можно пересчитать под другое число сотрудников.

**Коротко:** один сервер, один домен, статический IP с открытым портом 25 и отдельный
носитель под резервные копии. Платного ПО не требуется: Corvex — open source (Apache-2.0),
Docker и Ubuntu бесплатны, сертификат Let's Encrypt бесплатный.

---

## 1. Сервер

Расчёт на **50 почтовых ящиков** (первый выкат).

| Параметр | Требование | Зачем / что будет без этого |
|---|---|---|
| Форм-фактор | 1 физический сервер или 1 ВМ с SSD | Всё развёртывание — один `docker-compose` |
| CPU | **4–6 vCPU** | 12 Java-сервисов + поиск + антивирус; меньше — медленный вход и поиск |
| RAM | **16 ГБ минимум, 24 ГБ комфортно** | Elasticsearch 2,5 ГБ, PostgreSQL 2 ГБ, ClamAV 2–3 ГБ, 12 JVM. На 8 ГБ контейнеры будут падать по памяти |
| Диск под ОС | **100 ГБ SSD** | Windows Server + образы контейнеров (~25 ГБ) + кэш сборки |
| Диск под данные | **100 ГБ SSD** | почта, база, индекс поиска, файлы |
| Тип диска | **только SSD** | на HDD открытие ящика — секунды вместо мгновенного |
| Резервные копии | **отдельный носитель 100–200 ГБ** (внешний диск, NAS, сетевая папка) | копии на том же диске не защищают ни от отказа диска, ни от шифровальщика |
| ОС | Windows Server 2019/2022 **или** чистый Ubuntu Server 24.04 LTS | на Windows нужен Hyper-V и Linux-VM; чистый Linux проще в эксплуатации |
| Лицензии | Windows Server — существующая корпоративная; Ubuntu, Docker, Corvex — бесплатно | платных компонентов в стеке нет |

Если ящиков будет 100 — диск данных 200 ГБ, резервные копии 200 ГБ. Формула и таблица
для других масштабов: [`SIZING.md`](SIZING.md) §3.

## 2. Сеть

| Требование | Зачем / что будет без этого |
|---|---|
| **Статический публичный IPv4** (не за NAT/CGNAT провайдера) | без него не работают MX-записи и приём почты |
| Возможность установить **PTR-запись** (обратная зона) = `mail.<домен>` | без PTR письма уходят в спам у получателей (Gmail, Mail.ru, Яндекс) |
| **Открыт входящий TCP 25** | приём почты от внешних серверов; **главный блокер**, многие провайдеры закрывают |
| **Открыт исходящий TCP 25** | отправка наружу; при закрытом — письма не уходят вообще |
| Входящие TCP 80, 443 | веб-интерфейс, API, чат, выпуск сертификата |
| Входящие TCP 587 | отправка почты из почтовых клиентов (Thunderbird, Outlook) |
| Входящие TCP 143, 993 (IMAP) и 110, 995 (POP3) | доступ из почтовых клиентов; по умолчанию выключены, включаются после приёмки |
| Исходящий доступ к интернету (443) | обновление антивирусных сигнатур, пакеты, Let's Encrypt |
| Порт 25 проверяется **до** всех работ | если провайдер его не открывает — нужен внешний SMTP-релей, это отдельное согласование и деньги |

Порты 5432 (PostgreSQL), 6379 (Redis), 5672 (RabbitMQ), 9200 (Elasticsearch) наружу
**не открываются** — они работают во внутренней сети Docker.

## 3. Домен и DNS

Нужен домен для почты (например `company.ru`) и доступ к его DNS-зоне — свой или через
заявку провайдеру. Записей немного, все готовлю я:

| Запись | Значение | Назначение |
|---|---|---|
| `A` | `mail.company.ru` → публичный IP сервера | веб-интерфейс и почта |
| `MX` | `company.ru` → `mail.company.ru` (приоритет 10) | приём почты на домен |
| `TXT` (SPF) | `v=spf1 mx -all` | защита от подделки отправителя |
| `TXT` (DKIM) | `dkim._domainkey` — публичный ключ, выдам | подпись писем; без неё — спам |
| `TXT` (DMARC) | `_dmarc` → `v=DMARC1; p=quarantine; ...` | политика для получателей |
| `TXT` (autodiscover) | `autoconfig.company.ru` — выдам | автопастройка Outlook/Thunderbird |
| `PTR` | у провайдера: IP → `mail.company.ru` | см. раздел «Сеть» |

Если нужен только внутренний пилот без внешней почты — домен и PTR не требуются,
достаточно локального имени и самоподписанного сертификата. Внешняя переписка тогда
не проверяется, и это надо зафиксировать заранее.

---

## 4. Сертификат

| Вариант | Что нужно от ИТ |
|---|---|
| Публичный домен | ничего, кроме открытого 80 порта: Let's Encrypt выпускается автоматически и бесплатно |
| Внутренний домен | сертификат от корпоративного УЦ на `mail.company.ru` (файлы `.pem`: сертификат + ключ) |
| Пилот | самоподписанный на 90 дней создаётся скриптом, браузер будет предупреждать |

## 5. Доступы и учётные записи

| Что | Зачем |
|---|---|
| Локальный администратор сервера (или SSH-доступ в Linux-VM) | установка и запуск |
| Право менять DNS-зону либо контакт, который вносит записи по заявке | SPF/DKIM/DMARC/MX без этого не заработают |
| **Отдельный внешний почтовый ящик** для алертов (не на этом сервере) + пароль приложения | если сервер упадёт, он сам об этом не сообщит |
| 2–3 тестовых ящика на домене организации | приёмка: два пользователя, групповые действия, файлы |
| Один ящик на внешнем провайдере (Mail.ru/Яндекс/Gmail) | проверка входящей и исходящей почты «снаружи» |
| Учётные данные корпоративного прокси, если выход в интернет через него | обновление антивируса и выпуск сертификата |

AD/LDAP на этом этапе **не нужен**: учётные записи создаются в веб-интерфейсе
(первый суперадмин — через мастер первого запуска).

---

## 6. Что нужно согласовать отдельно

1. **Корпоративный антивирус/EDR на сервере.** Исключения для Hyper-V, Docker и томов
   данных нужны обязательно: иначе сканер блокирует файлы виртуальных дисков и сервисы
   падают. Альтернатива — отдельный хост под пилот.
2. **Название домена для почты** и кто отвечает за репутацию IP: новый IP без истории
   первое время чаще попадает в спам, это нормально и лечится постепенным объёмом.
3. **Куда кладём резервные копии**: отдельный диск, NAS или сетевая папка, и сколько
   копий храним (минимум 2, лучше 3 — история на месяц).
4. **Регламент на 72 часа наблюдения** после выката: кто дежурит и по какому номеру
   звонить при сбое почты.

---

## 7. Чего НЕ требуется

- Покупка почтовых лицензий, Exchange, антиспам-подписок: в стеке SpamAssassin и ClamAV.
- Отдельная СУБД или отдельный сервер поиска: всё в одном Compose.
- AD/LDAP, Outlook, мобильные клиенты — отложены осознанно, для пилота не нужны.
- Публичный облачный сервис: данные остаются на вашем сервере.

---

## 8. Что будет проверено на этом сервере (приёмка)

1. Вход первого администратора, создание пользователей и групп, разграничение доступа.
2. Почта: входящее с внешнего ящика и исходящее наружу; SPF/DKIM/DMARC проходят;
   письмо видно в веб-интерфейсе без перезагрузки страницы.
3. Почтовые клиенты: Thunderbird по IMAP (993) и POP3 (995), отправка через 587.
4. Веб-интерфейс: RU/EN, Chrome 109 (Windows 7) и мобильная ширина.
5. Чат, календарь с напоминанием на почту, «Файлы» с папками и ссылкой на файл
   (проверка открытия без входа, отзыв ссылки, запрет посторонним).
6. Антивирус: тестовый EICAR не проходит, при недоступном ClamAV загрузка блокируется.
7. Резервная копия → восстановление → откат, проверка целостности по манифесту SHA-256.
8. 72 часа работы под нагрузкой: нет перезапусков контейнеров, метрики и алерты приходят.

Критерий готовности пилота: все восемь пунктов пройдены и записаны с датой и версией.
До этого почтовые потоки организации на сервер не переводятся.

## 9. Порядок работ (одна неделя после получения доступов)

| День | Что делаем | Что нужно от ИТ |
|---|---|---|
| Пн | сервер, ОС, Docker, первый запуск без домена | доступ к серверу |
| Вт | домен, DNS-записи, сертификат, вход и админка | правка DNS-зоны |
| Ср | внешняя почта: входящая 25, исходящая, PTR, DKIM | открытый 25 в обе стороны, PTR |
| Чт | клиенты, чат, календарь, файлы, алерты | тестовые ящики, внешний ящик для алертов |
| Пт | резервная копия → восстановление → откат, старт 72 часов наблюдения | место под копии |

## 11. Риски, о которых нужно знать заранее

| Риск | Последствие | Как снимаем |
|---|---|---|
| Провайдер не открывает порт 25 | почта не ходит совсем | проверяем до начала работ; при отказе — внешний SMTP-релей (отдельная заявка и расходы) |
| Нет PTR или он не совпадает с именем | письма в спаме у получателей | запрашиваем PTR вместе с IP |
| Новый IP без репутации | первые дни часть писем в спаме | отправляем постепенно, следим за DMARC-отчётами |
| Мало RAM (8–12 ГБ) | контейнеры падают по памяти, письма теряют темп | 16 ГБ минимум, 24 ГБ с мониторингом |
| Корпоративный антивирус на хосте | блокирует тома Hyper-V/Docker | исключения или отдельный хост |
| Бэкапы на том же диске | потеря данных при отказе диска или шифровальщике | отдельный носитель + проверенное восстановление |
