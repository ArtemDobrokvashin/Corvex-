# Проверка фронтенда на своём компьютере

Короткая инструкция: как поднять интерфейс локально, что нажать и что считать
результатом. Ничего из этого не требует Docker, базы и Java — только Node.js.

## 0. Что понадобится

- Node.js `^22.22.2 || ^24.15.0 || >=26` (`node -v`) и npm `>=10` (`npm -v`).
  Другая версия — `npm ci` откажется работать: это прописано в `engines`.
- Свежий клон ветки с исправлениями (после мержа — `main`).

Проверка версии:

```powershell
node -v
npm -v
```

## 1. Установка

```powershell
cd frontend
npm ci
```

`npm ci` ставит ровно те версии, что зафиксированы в `package-lock.json`. Если он
ругается на версию Node — обновите Node, а не подменяйте `npm ci` на `npm install`.

## 2. Автотесты и сборка

```powershell
npm test          # Vitest, ~10-20 секунд
npm run build     # TypeScript + продакшн-сборка (modern + legacy)
```

Критерий:

- `npm test` — все тесты зелёные, без `skipped`;
- `npm run build` — завершился успешно, в `frontend\dist\assets` есть обычные файлы
  и хотя бы один `*-legacy-*.js`.

## 3. Живой интерфейс без сервера (демо-режим)

```powershell
npm run dev
```

Откройте `http://localhost:5173` и нажмите **«Посмотреть демо без сервера»**.
Демо-данные лежат внутри фронтенда, backend не нужен: письма, чат, админка и
календарь работают на снимке данных. Сверху видна жёлтая плашка демо-режима —
это нормально, она и должна быть.

Если порт 5173 занят — Vite возьмёт следующий и напечатает адрес в консоли.

## 4. Чек-лист приёмки интерфейса

Отмечайте только то, что действительно видели.

- [ ] вход открывается без белого экрана и без ошибок в Console (F12);
- [ ] переключатель RU/EN меняет интерфейс, даты и демо-данные;
- [ ] жёлтая плашка демо-режима видна;
- [ ] почта: папки, список, открытие письма, ответ, новое письмо;
- [ ] вложение открывается на просмотр;
- [ ] чат: комнаты, отправка сообщения, реакции; длинное слово не ломает вёрстку;
- [ ] админка: пользователи, группы, чекбоксы прав, аудит;
- [ ] календарь: создание события, повтор;
- [ ] ширины 360, 768 и 1366 px — без горизонтального скролла;
- [ ] масштаб 200 % (Ctrl + `+`) не ломает раскладку;
- [ ] тёмная тема переключается и не «слепит» контрастом.

## 5. Что делать с найденным

Пришлите: экран, шаги до дефекта и текст из Console. Секреты, реальные письма и
`.env` в переписку не попадают — в демо-режиме их и не требуется.

## 6. Чего в демо-режиме нет

Демо показывает интерфейс, а не сервер. Поэтому здесь **не проверяются**: реальная
отправка и приём почты, IMAP/POP3, вход по паролю через API, WebSocket-чат между
двумя людьми, алерты и бэкапы. Это делается на стенде после установки — см.
[`TESTING.md`](TESTING.md) §4 и [`UBUNTU.md`](UBUNTU.md).

## 7. Когда появится сервер

Полный подъём стенда — [`UBUNTU.md`](UBUNTU.md) и [`INSTALL.md`](INSTALL.md).
Отдельно до первого запуска стоит проверить два пункта, из-за которых чистый
сервер обычно «не открывается»: `vm.max_map_count` (Elasticsearch) и
`CORVEX_WEB_ORIGINS` (вход по IP вместо имени).
