## 4. Что осталось незакрытым (честный список)

Эти пункты не блокируют установку, но их надо помнить:

1. **Джоба `e2e` не включена в CI.** Готовый текст — `docs/ci/e2e-job.yml`,
   его нужно вставить в `.github/workflows/ci.yml` руками: у автоматизации нет
   права `workflows`. E2E ни разу не прогонялись.
2. **Подпись в SMTP-submission не подключена** — только в веб-отправке.
3. **Цепочки в UI** строятся по теме и отправителю, а не по `References`.
4. **Офлайн-снимок без service worker** — полноценного офлайна нет.
5. **«Скачать все» вложения** отдаёт файлы по одному, без ZIP.
6. **Android-клиент** в `main`, но в CI не собирается.
7. Хвосты эксплуатации: Let's Encrypt, healthcheck postgres, UTF-8 в
   PowerShell-логах, bash-версии `preflight-server` / `first-run` / `alerts` /
   `diagnose-mobile-access`, ~175 осиротевших `.eml` в спуле.

## 5. Как это чинилось (чтобы не искать заново)

Причина, из-за которой Java-CI был красным дольше всего, оказалась скучной:
`RawMessageSpool.delete()` объявляет `throws IOException`, а тест
`OutboxServiceTest` вызывал `verify(spool).delete(...)` без `throws`. Файл
**не компилировался**, а ошибка компиляции тестов — это не падение теста:
`testFailureIgnore`, отчёты surefire и аннотации её не ловят. Отсюда всё
«странное» поведение бисекции.

Полезное на будущее:

- локально `mvn` недоступен (нет JDK, Maven Central закрыт), логи CI и
  артефакты тоже недоступны — проверка только прогонами CI;
- бисекция по тест-классам через `maven-compiler-plugin/testExcludes`
  работает, но файл всё равно компилируется: «выключить» класс можно только
  удалив его физически;
- workflow-команды из тестов (`::error::`) в аннотации **не попадают**, а из
  шагов npm — попадают.
