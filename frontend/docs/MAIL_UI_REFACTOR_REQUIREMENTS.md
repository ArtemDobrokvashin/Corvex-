# Требования к рефакторингу почтового интерфейса (по макетам)

## Обзор
Реализовать почтовый интерфейс в духе предоставленных макетов (Recruitify-style): светлый элегантный интерфейс, тёмный сайдбар навигации, зелёный акцент, карточки писем, панель вложений с иконками типов файлов, безопасное отображение HTML писем с картинками. Без emoji в интерфейсе. Без заглушек — где требуется бэкенд, описано ниже.

## Что требует бэкенда (создать отдельные задачи)

### 1. Прокси изображений в HTML письмах
**Почта нужна:** бэкенд endpoint для безопасного отображения внешних изображений в письмах.

**Проблема:** HTML письма содержат `<img src="https://external.test/image.png">`. Прямая загрузка раскрывает IP получателя, позволяет трекинг (пиксели открытия), и может содержать вредоносный контент.

**Решение:** бэкенд предоставляет endpoint `/api/v1/mail/images/proxy?url=<encoded>&messageId=<id>`:
- Принимает подписанный URL изображения и messageId
- Проверяет подпись (предотвращает подмену)
- Загружает изображение без куки/заголовков получателя
- Ограничивает размер (например, 5 МБ) и content-type (только изображения)
- Возвращает изображение с правильными заголовками
- Никогда не forwards IP получателя к внешнему серверу

**Фронтенд:** подменяет `src` внешних изображений на прокси-URL, предлагает кнопку "Показать изображения" для писем с удалённым контентом.

### 2. Подпись ссылок в письмах
**Почта нужна:** бэкенд подписывает внешние ссылки в HTML письмах через промежуточную страницу редиректа.

**Решение:** endpoint `/api/v1/mail/redirect?to=<encoded>&messageId=<id>&sig=<signature>`:
- Проверяет подпись
- Показывает промежуточную страницу с предупреждением, если домен ссылки отличается от отображаемого текста
- Выполняет редирект только после подтверждения пользователем

### 3. API вложений (уже есть)
`GET /api/v1/mail/messages/:id/attachments/:partIndex` — уже реализовано в mailApi.ts. Требует только бэкенда mail-storage-service.

## Что реализуется на фронтенде (без бэкенда)

### 1. Дизайн по макетам (MailPage.tsx)
- **Тёмный сайдбар** слева (dark navy, как в макетах) с иконками папок
- **Светлый контент** с карточками писем
- **Зелёный акцент** (как в макетах: кнопка Compose, выделенные элементы, индикаторы непрочитанного)
- **Карточки писем**: аватар отправителя слева, имя, тема, дата, snippet, маркер непрочитанного, звёздочка важности, иконка скрепки при вложениях
- **Панель вложений** в письме: иконки типов файлов (PDF, DOCX, JPG, и т.д.) с размером файла
- **Чистая типографика**: system-ui / Inter, без избытка карточек
- **Кнопка Compose** плавающая или внизу списка
- **Без emoji**: убрать EmojiPicker из ComposePanel и других мест

### 2. Безопасный HTML с картинками (mailHtml.ts)
Текущая реализация bloqueирует ВСЕ внешние ресурсы (img-src data:). Нужно:

- **Безопасность по умолчанию:** скрипты, iframe, формы, стили — заблокированы (уже есть)
- **Изображения:** по умолчанию показываются только data: и base64 изображения; внешние изображения заменяются на плейсхолдер с кнопкой "Показать изображения"
- **При клике "Показать изображения":** внешние изображения загружаются через бэкенд-прокси (когда доступен), или показываются с предупреждением
- **data-original-src:** сохранять оригинальный URL изображения для отладки
- **Sandbox iframe** с строгой CSP (уже есть, но нужно расширить для img-src через прокси)
- **Ссылки:** все внешние ссылки оборачиваются в подписанный редирект (когда бэкенд доступен)

### 3. Убрать emoji
- Убрать `EmojiPickerButton` из `ComposePanel` и `EmojiPicker.tsx` из интерфейса
- Оставить только если бэкенд требует (но пользователь сказал "без emoji")

## Критерий приёмки
- Интерфейс соответствует макетам (тёмный сайдбар, зелёный акцент, карточки писем, панель вложений)
- HTML письма отображаются безопасно: нет скриптов, нет трекинг-пикселей по умолчанию, изображения показываются через прокси или по запросу
- Нет emoji в интерфейсе
- tsc, vitest, build проходят успешно
