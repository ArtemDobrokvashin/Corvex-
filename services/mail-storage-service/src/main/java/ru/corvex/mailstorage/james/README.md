# Незавершённый клиент James JMAP

Экспериментальный код без регистрации в Spring и без подключения к API, не
развёрнут и не предназначен для production. Вызовы ограничены операциями чтения,
используют фиксированный HTTPS origin, не следуют redirect и не логируют токен.
Это только транспорт: он не проверяет JWT Corvex, не выдаёт токены James, не
связывает accountId с owner UUID и не обеспечивает RBAC, AV, TTL или отзыв.
Нельзя открывать этот клиент через API или направлять в него пользовательские
параметры до реализации и испытания этих механизмов.

Исходная версия прошла Maven/JUnit на ПК (12 тестов вместе с policy).
Затем транспорт изменён для ограничения размера и времени чтения всего тела;
эта новая версия ещё не прошла Maven/JUnit и живой James. HTTPS с реальным
сертификатом и поведение при отказах также не проверены. Код опубликован в рабочей ветке для лабораторной проверки; не включать в
работающий сервис, пока эти проверки не пройдены на изолированном стенде.

`JamesMailboxBinding` — экспериментальная проверка согласованности UUID,
права чтения, активного серверного сопоставления и первичного аккаунта сессии.
Она не создаёт и не подтверждает достоверность этих сведений, не проверяет
подпись токена и не предотвращает отзыв во время операции. Требуются безопасный
реестр сопоставлений, актуальный статус/права, выпуск отдельного токена James,
связывание его с полученной сессией и интеграционные испытания. Не подключена
к API и не означает переноса или миграции почты.

Экспериментальные `JamesReadTokenIssuer` и `JamesOwnMailboxReader` объединяют
проверку соответствия, выпуск RS256-токена на 60 секунд, проверку primary account
и чтение папок через JMAP. Пока они **не подключены к API**: доверенный каталог
сопоставлений, проверка JWT Corvex, актуальный статус/права и управление ключами
не реализованы. Токен James — полноправный bearer для ящика, а не read-only;
подпись отдельным закрытым ключом и изоляция обязательны. Не считать `iss`/`aud`
проверенными James 3.9.1 и не использовать ключ авторизации Corvex. Токен не
возвращать клиенту и не записывать в журналы. Реальное соединение James, отзыв
прав, TLS и ошибки доверенных upstream ещё не испытаны.

`JamesOwnMailboxAccess` и `JdbcJamesMailboxRegistry` — отключённый прототип
получения связи по UUID из серверного реестра и проверки ACTIVE через
`auth-service`. SQL-образец хранится в `experiments/james-postgres-lab/integration/`
и **не является миграцией**. Создание и изменение соответствий с проверкой
владения, аудитом и отдельными правами ещё не реализовано. При отказе справочника
или БД доступ не разрешается. Устаревание прав в JWT сохраняется до его expiry:
проверка текущего состояния пользователя не является проверкой отзыва прав.
Подпись JWT на этом уровне не проверяется: использование возможно только после
проверки Spring Security с корректными validators issuer/времени и ключами.
Этот слой не подключён к webmail и не прошёл live-тест.

Для будущего подключения добавлена проверка актуального `MAIL_READ_OWN` через
внутренний admin-service перед выпуском James-токена; нужны и право в JWT, и
текущее право. Ошибка, некорректный ответ или отзыв закрывают доступ. Возможная
гонка отзыва после проверки до завершения запроса сохраняется; сам bearer может
действовать до 60 секунд. Внутренний транспорт и секрет нужно защитить, клиент
не зарегистрирован и ещё не проверен live с admin-service/James.

`JamesFolderMapper` преобразует JMAP Mailbox/get в существующий `FolderView`.
UUID детерминирован и связан с owner UUID, account ID и ID папки James; обратное
разрешение допускается только по свежему списку текущего владельца. Этот UUID
не является защитой доступа. При изменении account ID изменятся и UUID папок;
перед внедрением нужна политика совместимости, миграции и удаления/воссоздания
ящика. Слой всё ещё не подключён к контроллеру; сообщения и операции записи
не переведены.

Подготовлено чтение первой страницы метаданных писем через `Email/query` и
`Email/get`, только после серверной проверки доступа и разрешения UUID папки
по свежему списку владельца. Проверяется account ID, принадлежность письма к
папке и полнота ответа; конкурентное исчезновение письма пока даёт ошибку.
Это внутренняя JMAP-модель, не публичный `MessageListItem`: IMAP UID, курсор,
постраничная навигация, AV/spam provenance и безопасное чтение содержимого ещё
не реализованы. Новый путь отключён и пока не прошёл Maven/live тесты.

Для интерфейса подготовлен отдельный preview-формат без фиктивного IMAP UID.
Он сохраняет статус антивируса как `UNVERIFIED`: JMAP сам по себе не является
доказательством сканирования. Идентификатор письма привязан к owner+account+ID
James и остаётся тем же при перемещении между папками. Пагинация использует
`position` и `queryState`, а при изменившемся состоянии требует заново загрузить
первую страницу. Этот механизм и новое отображение ещё не прошли live/JUnit
проверку, не подключены к frontend/API, и не решают совместимость со старым
UID-курсорным контрактом, загрузку вложений или AV-проверку.
