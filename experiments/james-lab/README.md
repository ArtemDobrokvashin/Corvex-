# Изолированный стенд Apache James — только синтетические данные

Это начальный прототип исследования, **не интеграция в Corvex и не конфигурация
для эксплуатации**. Не использовать настоящие письма, учётные записи и пароли.
Основной `docker-compose.yml`, тома и рабочий сервер не изменяются. Стенд не
публикует порты и использует отдельную внутреннюю сеть Compose. Внутри сети
доступны публично известные демо-пароли James: не
подключать к этой сети другие сервисы и не использовать на ней реальные данные.
Тест включает STARTTLS до входа, но не проверяет подлинность самоподписанного
демо-сертификата. Это допустимо только для изолированной лаборатории с синтетическими
данными: в рабочей системе обязательна полноценная проверка сертификата и имени.

Upstream `apache/james:demo-3.9.1` демонстрационный, а не выбранная финальная
редакция. Исходный Dockerfile demo 3.9.1 опирается на `jpa-latest` при сборке,
поэтому тег сам по себе не доказывает происхождение зависимостей: перед реальным
использованием нужна проверка digest, состава и лицензий. POP3 в upstream demo
отключён. H2/JPA — не решение о PostgreSQL, производительности или сохранности.
У этой конфигурации нет тома: данные исчезнут при пересоздании контейнера.
Никаких выводов о долговечности она не даёт.

## Предварительный запуск на отдельной машине с Docker

Команды приводятся для будущего тестового стенда, **не выполнять на рабочих данных**.
Нужны доступ к Docker registry и свободные ресурсы; тест может загружать образы.
Из корня репозитория:

```sh
docker compose -p corvex-james-lab -f experiments/james-lab/compose.yaml up -d james
docker compose -p corvex-james-lab -f experiments/james-lab/compose.yaml run --rm -e JAMES_LAB_CONFIRM=synthetic-only probe
```

Проверка ожидает демо-пользователей upstream `user01@james.local` и
`user02@james.local`, ограниченно ждёт запуска, создаёт уникальное синтетическое
письмо с бинарным вложением, проверяет байты после IMAP APPEND и COPY, флаг, MOVE копии и сохранность
оригинала, а также отсутствие этого письма во входящих второго пользователя.
При отсутствии IMAP MOVE проверка завершается ошибкой, а не пропуском. Она не удаляет созданные объекты.
Ошибка запуска или несовпадение сборки демо-образа — FAIL, а не доказательство
ошибки Corvex. Сохраните журналы и полный вывод; не публикуйте секреты.

Остановить контейнеры, не удаляя их: `docker compose -p corvex-james-lab -f
experiments/james-lab/compose.yaml stop`. Никаких `down -v`, удаления томов или
операций с проектом `corvex`. Окончательную очистку лаборатории проводить отдельно
после проверки имени проекта и согласования. Не запускать этот стенд на боевом
сервере и не предоставлять ему доступ к существующим томам.

## Необходимые следующие шаги

* Запустить и зафиксировать результат, проверить реальную сборку и конфигурацию.
* Подготовить воспроизводимый persistent стенд и отдельно проверить рестарт,
  аварийное завершение, согласованный backup/restore, MOVE/флаги/EXPUNGE/POP3,
  параллельные операции, SMTP, вложения, тесты нагрузки и повреждения данных.
* Проверить подключение к идентификации Corvex, отзыв доступа, app-password,
  API webmail, поиск, события, AV/спам и настройки SMTP. Определить единственный
  источник истины и как безопасно импортировать данные на копии без потери UID,
  флагов и прав. Конкретная схема адаптера ещё не выбрана.
* Установить применимые лицензии всех образов и зависимостей, проверить digest,
  поддержку версии и безопасность сети. Готовый движок не отменяет тестирования.

### Проверка после обычного перезапуска (подготовлена, ещё не испытана на James)

Дополнительные режимы `JAMES_LAB_MODE=seed` и `verify` используют один и тот же
`JAMES_LAB_MARKER` — строго 32 строчных шестнадцатеричных символа. Seed откажется
создать дубликат и сравнит оригинальные MIME-байты с прочитанными; verify ищет
ту же метку и сравнивает те же байты без записи. Оба режима требуют
`JAMES_LAB_CONFIRM=synthetic-only`. Для теста следует сначала записать сообщение,
затем отдельно перезапустить *тот же* контейнер и выполнить verify с той же меткой.
Пересоздание контейнера или очистка уничтожит данные лаборатории: тома нет.
Обычный restart не проверяет потерю питания, корректность backup, персистентность
при пересоздании или production-конфигурацию. До исполнения не считать PASS.

`JAMES_LAB_MODE=diagnose` читает тестовый INBOX без изменения флагов и выводит
количество сообщений, результатов HEADER SEARCH, сообщений с маркером при
побайтовом чтении и точных совпадений. Останавливается при более 100 письмах или
несоответствии количества SELECT и SEARCH ALL. Не выводит содержимое писем.
Эта диагностика только для синтетической лаборатории; она не доказывает
сохранность данных, не исправляет индекс и не является тестом восстановления.

### Сводный прогон

Режим `JAMES_LAB_MODE=suite` запускает три независимых сценария: базовый IMAP
(как один сценарий), локальную SMTP-доставку синтетического вложения во второй
demo-ящик и чтение ранее сохранённого письма, если передан `JAMES_LAB_MARKER`.
Независимые сценарии продолжаются после ошибок. Итог — PASS/FAIL/SKIP и ненулевой
код при FAIL; SKIP не означает успех. Сетевые ошибки могут удлинить ожидание.
SMTP проверяется только для двух фиксированных demo-адресов; сообщение будет
создано в лабораторном ящике. Режим не перезапускает сервер, не удаляет письма,
не переиндексирует, не проверяет боевые TLS, AV, POP3, сбои или backup/restore.
Он не заменяет integration/crash-тестов и не подключён к Corvex. Логи могут
содержать ответы демо-сервера: перед передачей проверить на секреты.

Для изолированной PostgreSQL-сборки SMTP submission проверяется с
`JAMES_LAB_SMTP_MODE=submission`: порт 587, STARTTLS, вход demo-пользователя.
Сертификат в лаборатории не проверяется. Это не настройка для реальных данных.
