# Эксперимент: жизненный цикл ссылок на тело письма

Изолированная модель на Python/SQLite, **не подключена к приложению**, не читает и
не удаляет файлы, не мигрирует данные. Нужна, чтобы отработать базовый инвариант:
объект с активными ссылками не может перейти в GC_PENDING; к GC_PENDING нельзя
добавить ссылку. Закрепление и удаление ссылки вместе с переводом состояния
происходят в транзакции. Тесты используют только временную SQLite-базу:

```sh
python3 -m unittest discover -s experiments/mail-reference-model -v
```

SQLite сериализует записи иначе, чем PostgreSQL. Результат не доказывает
безопасность PostgreSQL, конкурентность реальных сервисов, работу нескольких
процессов, durability или безопасность физической очистки. Нет worker, rollback
файловых операций, политик хранения и интеграции с доставкой/IMAP/webmail.
Следующий этап — реализация под PostgreSQL с блокировкой строки тела и защитой
всех путей записи, затем реальные интеграционные тесты и recovery; до того
автоматическое физическое удаление не включать. Прямой DELETE ссылок в этой
модели не включает retirement автоматически: инвариант отсутствия ссылок при
GC_PENDING защищён триггером, но требуется обеспечивать вызов протокола для
полноты очистки. Не использовать эксперимент для пользовательских данных.
