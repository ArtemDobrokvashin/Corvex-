# Экспериментальная сверка переноса James

`compare_manifests.py` — **офлайн-компаратор подготовленных манифестов**, не
экспортёр, не переносчик и не инструмент переключения. Он не подключается к
серверам и не изменяет письма. Тестировался только на синтетических данных.
Не использовать как единственный критерий переноса или production cutover.

Оба файла — UTF-8 JSON, не более 128 МиБ каждый. Пример исходного файла:

```json
{"version":1,"kind":"source","snapshot_id":"source-snapshot-01","records":[
  {"source_id":"f61b2fbc-7419-4eb0-8992-35841d0c77af", "mailbox":"user@example.test", "folder":"Inbox", "sha256":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa", "size":20, "flags":["seen"]}
]}
```

В целевом файле `kind` равно `target`, каждая запись дополнительно содержит
`target_id`: фактический ID письма James, полученный из доверенного реестра
импорта. `source_id` — UUID записи исходной системы, **не Message-ID заголовка**;
байты и размер — полные исходные RFC 5322 данные без преобразований, SHA-256
строчными hex. `mailbox` и `folder` — канонические значения после проверенного
сопоставления; flags — множество из `seen`, `answered`, `flagged`, `draft`,
`deleted`. Дополнительные флаги, ключевые слова, даты, UID и подписки пока не
проверяются. Разные записи с одинаковым содержимым остаются разными письмами.

```sh
python experiments/james-migration/compare_manifests.py source.json target.json
python -m unittest discover -s experiments/james-migration -v
```

Вывод содержит только агрегаты. Код 0 означает совпадение указанных записей,
1 — обнаружены расхождения, 2 — ошибка/некорректный или пустой файл. Не
присылайте манифесты: они содержат персональные данные и должны храниться с
ограниченным доступом. Данные и файлы не создаются этим компаратором.

**Ограничения:** формирователи манифестов и доверенный журнал сопоставлений
ещё не реализованы; поддельные, неполные, устаревшие или несогласованные
манифесты могут совпасть. `snapshot_id` — только описание источника, не
проверка консистентности. Для этой первой модели требуется уникальный source ID
и целевой ID в пределах ящика; копии с общим target ID в разных папках будут
отклонены и должны быть отдельно исследованы. Нет проверки полноты списка
ящиков/папок, папок без писем, прав доступа, MIME-вложений отдельно, связности
индекса, очередей SMTP, доставки или дублей вне указанного набора. Пустой набор
отклоняется; проверка реальных пустых ящиков потребует другого подхода.

Для готовности нужны согласованный снимок или окно записи, фиксированный scope,
доказательство полноты извлечения и журнал импорта с безопасным повтором,
сверка байтов, метаданных и протокольной доступности, интеграционные и
crash/restart/restore-тесты. После остановки старой записи потребуется
финальный delta-перенос; rollback не должен терять доставку после переключения.
