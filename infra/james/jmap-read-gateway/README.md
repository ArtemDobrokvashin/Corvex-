# Внутренний read-only JMAP gateway

В Compose-профиле `james-transition` сервис `james-jmap` использует этот
шлюз вместо прежнего nginx. Уже запущенный контейнер не обновляется сам:
нужно отдельно собрать образ и пересоздать только этот сервис. Сам профиль
James не включается и почтовые маршруты на него не переключаются автоматически.

Шлюз принимает только `GET /jmap/session` и один POST-вызов из `Mailbox/get`,
`Email/query`, `Email/get`. Пакеты из нескольких вызовов, операции записи,
загрузка/выгрузка, другие URL и сжатое тело отвергаются. JSON разбирается и
сериализуется заново, чтобы duplicate keys или escape-последовательности не
позволили другой интерпретации переданной James команды. Размер тела, ответа и
срок ожидания ограничены. На стороне James шлюз не следует redirect и не пишет
токены в лог.

`node --test infra/james/jmap-read-gateway/gateway.test.cjs` (Node 22) —
синтетические проверки; Dockerfile выполняет их при сборке. На ноутбуке в
существующем Compose кандидат собран и временно запущен: проверены TLS с
доверенным, недоверенным и неверным именем, с синтетическим James-аккаунтом —
session, Mailbox/get, Email/query и Email/get; пустые заведомо некорректные
запросы Email/import, Email/set, Mailbox/set, EmailSubmission/set и смешанный
batch получили отказ шлюза. Затем прежний nginx восстановлен и чтение и TLS
проверены повторно (PASS). Это не полная проверка всех способов обхода и не
AV, перенос реальных пользователей или проверка почтовых маршрутов.

Ограничение методов — не авторизация пользователя. Bearer остаётся полноценным
токеном James, поэтому требуется доверенная привязка владельца, актуальный RBAC,
короткий срок и защита ключей. Доступ к самому James через другую сеть,
WebAdmin, IMAP APPEND или иные каналы этот шлюз не ограничивает; в частности,
AV-overlay даёт сетевой доступ контейнеру ClamAV. Не выдавать токены браузеру.
Шлюз не проверяет AV и не является завершённым переносом на James.

`infra/james/candidates/jmap-read-gateway.compose.yml` и
`scripts/test-james-jmap-read-gateway.ps1` относятся к проверке при исходном
nginx. Скрипт намеренно откажется запускаться при другом baseline или при
существующем intent; не удалять marker и не повторять его автоматически.
Старый конфиг `infra/james/jmap-nginx.conf` сохранён как справочный вариант,
но он не фильтрует JMAP-методы внутри POST и не заменяет этот шлюз.
