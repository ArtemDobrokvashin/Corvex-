# Локальная история Corvex — НЕ ПУБЛИКОВАТЬ

Никогда не добавлять файл в Git index, коммиты или GitHub. Это локальная краткая сводка, а не полный дословный диалог. Не включать секреты или содержимое писем. Обновлять после важных решений. При публикации тщательно проверять список добавляемых файлов; не использовать `git add -A`.

## Задача и решения
- Corvex — open-source корпоративная платформа, 12 сервисов, почта и чат, self-hosted, до 1000 пользователей, единый Compose на Windows Server, RU/EN, Chrome 109 и mobile. Цель — ограниченный пилот; безопасность важнее срока.
- Выбран предварительный путь: оценить Apache James как единый почтовый движок на отдельном стенде, не писать протокольные парсеры с нуля. Решение о production-сборке и миграции ещё не принято.
- Реальные письма не перемещать, не архивировать и не удалять до приёмки. Семь найденных orphan-копий сохранить. Никаких `git clean`, `reset --hard`, `down -v`, prune. На ПК — одна логическая команда за раз и остановка на ошибке.
- UI: современный светлый дизайн, папки вертикально, личные папки по умолчанию, RU/EN; нужны черновики, подписи, HTML/CID, внешние картинки только после разрешения, массовые операции и пересылка оригиналов, личный диск, календарь и контакты. Права из шести групп объединяются; директору аналитика без чужой почты; бухгалтеру рассылка; менеджеру собственное подразделение. Конференции, Outlook и AD/LDAP отложены.
